# 難タスク実行プロトコル

## 目的

難しい作業を「考え続ける状態」にせず、証拠、決定、実装、検証の境界を持つ小さな作業列へ変換する。

## 手順

1. `AGENTS.md` と `docs/README.md` を読み、正本と制約を特定する。
2. 現在のブランチ、差分、生成物、対象アセットと `.meta` の状態を確認する。
3. 要求を一文で固定し、非対象を列挙する。
4. 不明点を `Confirmed`、`Provisional`、`Open`、`Pending Evidence` に分類する。
5. 作業を入力確認、設計判断、独立実装、静的検証、Unity/ClientSim検証、実機確認へ分ける。
6. 各単位に完了条件、編集範囲、失敗時の戻し方を設定する。
7. 最小の単位から実行し、結果に応じて次を更新する。
8. 仕様、ADR、テスト記録、権利記録を正本へ反映する。

## SubAgentを使う場合

利用者が許可した場合に限り、最大1体、深さ1で使う。委譲文には目的と期待する出力、読取範囲と編集可能範囲、変更禁止対象、Unity/VRChat固有制約、必須検証、報告形式を含める。

親は要件、設計、統合、最終検証、成果物の採否を保持する。シーン/Prefabを同時編集させない。

## 完了判定

- 変更が要求と一対一で対応している。
- 不要な生成物や無関係な整形が含まれていない。
- 必要な `.meta` が揃い、GUIDが意図せず変わっていない。
- 選択した検証が成功し、未実施の実機確認が明記されている。
- 新しい判断、リスク、第三者依存が該当する正本に記録されている。
