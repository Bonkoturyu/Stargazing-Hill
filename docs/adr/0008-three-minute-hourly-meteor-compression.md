# ADR 0008: 1時間相当の流星活動を毎時3分へ圧縮する

- 状態: Accepted
- 決定日: 2026-08-12

## Context

初期実装は毎時00分から25秒間、5秒waveを5回使い、1イベント最大20本としていた。これは描画負荷上の必須上限ではなく、初期演出用の暫定値だった。描画pool自体は4 Quadの再利用であり、イベント全体の流星数を20本へ固定する理由はない。

本ワールドは現実の東京の星空・月・流星群へ連動することを主題としているため、単純な「強・中・弱」のショーより、現実の観測レートを理解しやすい形へ時間圧縮する方針が適している。

## Decision

### 自然発生イベント

- 毎時 `HH:00:00` から `HH:03:00` までの180秒を流星イベント時間とする。
- この3分間は、その時刻付近に東京の暗い空で1時間観察した場合の期待流星数を時間圧縮して見せる。
- 総本数の固定20本上限は廃止する。
- 同時描画数は既存の4 Quad poolを維持する。総本数が増えてもGameObject/Renderer数を増やさない。
- 各流星の出現時刻はイベント全体へ決定論的に分散し、完全な等間隔にはせずseed由来のjitterを加える。
- 活動流星群がない、または放射点が地平線下で期待数が0になる場合は、1時間相当の散在流星として1〜2本を3分へ圧縮する。
- Late Joinは現在のネットワークUTCから3分イベント内の経過秒を求め、終了済み流星を再生し直さない。

### 本数の基準

IMO 2026のZHRをそのまま3分間の本数には使わない。ZHRは理想条件へ規格化された観測指標であり、東京から実際に期待できる見かけの本数とは異なるためである。

初期実装では、国立天文台「主な流星群」の日本付近・暗い空・極大時の1時間あたり目安をピーク基準値として使う。

| 流星群 | 極大付近の基準本数 / 1時間 |
|---|---:|
| しぶんぎ座 | 30 |
| 4月こと座 | 10 |
| みずがめ座η | 5 |
| みずがめ座δ南 | 5 |
| ペルセウス座 | 40 |
| 10月りゅう座 | 2 |
| オリオン座 | 10 |
| おうし座南 | 3 |
| おうし座北 | 2 |
| しし座 | 4 |
| ふたご座 | 60 |

実際のイベント本数は、上記基準に次を掛けて算出する。

1. 活動期間内の活動度
2. 東京から見た放射点高度係数

放射点高度係数は、その流星群が東京から取り得る最大高度を1として正規化する。これにより、低緯度側の放射点を持つ流星群が常に過小評価されることを避けつつ、地平線付近では本数を自然に減らす。

### 活動曲線

現時点の開始日→極大日→終了日を結ぶ三角形近似は暫定で継続する。ただし、流星群ごとにピーク幅が大きく異なることは既知であるため、将来はcatalogへ `peakWidthHours` / `activityProfile` 等を追加し、しぶんぎ座の鋭いピーク、オリオン座やおうし座の広い活動などを個別データで表現する。

### 強制デバッグプレビュー

自然イベントを180秒へ延長しても、Editor/VR調整の強制プレビューまで3分にすると確認効率が悪い。

そのため強制プレビューは従来どおり以下を維持する。

- 25秒
- 20本
- 5秒ごとに最大4本
- 選択流星群を強制
- 最初の1本をFireballへ固定
- ローカルのみ

これは自然イベントの本数・活動度を再現する機能ではなく、見た目と軌跡を短時間で確認するQA機能として明確に分離する。

## Consequences

- ふたご座やペルセウス座の極大付近では20本を超える流星を表示できる。
- 弱い流星群では3分間に数本だけとなり、流星群ごとの個性が明確になる。
- Rendererは最大4個のままで、総本数増加によるGPU draw対象の増加を避ける。
- 毎時イベントは花火のような短時間集中演出ではなく、3分間に散らした観察体験になる。
- 自然イベントと強制QAの時間は `MeteorController.NaturalEventDurationSeconds` / `DebugForcedPreviewDurationSeconds` の2定数を唯一の調整箇所とし、Sceneへ重複してserializeしない。
