# ADR-0009: Jacaranda一本木のQuest向けフロンドカード樹冠

- 状態: Accepted
- 決定日: 2026-08-12

## Context

ADR-0004は連結部品単位の選択でJacarandaを465,580 trianglesまで削減したが、同ADRの `Consequences` 自身が「Quest/iOSで実測が必要な負荷」であり「必要なら遠距離LODまたはbillboardを追加する」と保留していた。

実際に描画すると2つの問題が確認できた。第一に、葉を実ジオメトリのまま連結部品の6%だけ残す方式は、樹冠を「まばらな斑点」に変える。完全な葉部品だけを残すため個々の葉は正しいが、94%が失われた樹冠は向こう側が透けて見え、木として成立しない。第二に、幹を100%保持したため230,112 triangles、すなわち総量の約半分を単一の幹が占めていた。

VRChatのQuest向けワールド予算では、ワールド全体で5万triangles程度が実用上の目安である。この世界には既に密な草Meshと12,495個の星Quadがあり、一本木が465,580 trianglesを占める余地はない。

一方、Poly Havenの葉テクスチャ `jacaranda_tree_leaves_diff_1k.jpg` は個葉ではなく、**複合葉3枚を並べたアトラス**であり、対応するalpha maskを持つ。これはカード方式の樹冠にそのまま使える形式である。

## Options

- ADR-0004の連結部品選択の比率だけを調整する。
- 汎用QEMで葉ジオメトリごと簡略化する。
- 葉ジオメトリを捨て、葉テクスチャのフロンドをalpha test板（カード）として再構成する。
- 遠距離billboard LODを追加し、近距離は465,580 trianglesのまま維持する。

## Decision

- 葉submeshは実ジオメトリを完全に破棄し、alpha testのフロンドカードへ置き換える。カードのUVは葉アトラス内の複合葉3枚の矩形を指し、葉柄側の辺が枝に接する向きで割り当てる。
- カードは**位置を枝から、向きと分布を葉から**取る。片方だけに頼ると成立しない。
  - 目標点は、破棄する葉三角形の重心をボクセル集約した点とする。走査された樹冠が実際に葉を持っていた場所である。
  - カードの茎は、その目標点に**最も近い出荷枝Meshの表面点**へ置く。描画される木から生えることが保証される。
  - カードの向きは茎から目標点へのベクトルとする。方向が葉データ由来なので符号の曖昧さがなく、そこへ僅かな下垂とばらつきを加える。
  - カードごとに茎軸まわりのroll角も乱数化し、全カードが同一平面に揃わないようにする。
- フロンドの寸法は実物の複合葉（30〜45cm）を基準とする。カードを大きくすれば少数で樹冠を埋められるが、近距離で板が露見する。ただし茎と目標点の距離が空く箇所では、間引きで消えた小枝の分を橋渡しするため上限付きで伸長する。
- 位置・姿勢・frond選択はすべて決定的hashで決め、ベイクを再現可能にする。
- 幹と枝は走査形状を保つため、グリッド頂点クラスタリングで削減する。cellはtriangle目標に対して二分探索し、代表点はcell中心ではなく所属頂点の平均とする。
- 幹には枝より多い7,000 trianglesを割り当てる。幹は利用者が至近距離で接する唯一の面であり、強く削ると樹皮が平たい破片とねじれたリボンに折り畳まれる。
- 樹冠の陰影法線は各カードの平面法線ではなく、樹冠中心から外向きに膨らませた方向を使う。単一のdirectional lightの下で、板の集合ではなく1つの柔らかい塊として陰影が出る。
- 葉マテリアルは深い葉色でtintし、ambientを0.48から0.32へ下げる。
- 派生Meshは `Jacaranda_Quest.asset` とし、枝・幹・葉の3 submesh構成とmaterial順序はADR-0004から変更しない。
- ADR-0004の `Jacaranda_LOD0.asset` は成果物ではなく本ベイクの入力になる。原本FBXと同じく `SourceDownloads/` 配下の `.gitignore` 対象ローカル入力として扱い、リポジトリへは含めない。

## Consequences

一本木は465,580から19,507 trianglesへ、アセットは38MBから2.52MBへ縮小した。内訳は枝3,345、幹6,872、葉9,290（4,645枚のカード）である。茎から目標点までの距離は平均0.54、最大2.79 model unitで、葉は枝に接したまま走査時の樹冠形状を再現する。

カード寸法は自然さを直接左右する。1枚あたり0.76m相当で2,344枚とした版は、個々のカードが平たいシートとして読め、樹冠の下端が直線的な棚になり、真横を向いたカードが視界を横切る長い筋になった。実物の複合葉に近い0.50m相当へ縮め、枚数を4,645へ増やすことでいずれも解消した。カード法線の上向きバイアスも、水平な層を作るため0.5から0.30へ弱めている。

この配置方式に至るまでに2つの失敗をしている。記録として残す。

- 葉の位置にカードを置いた版は、葉を支えていた小枝が間引きで消えるため、葉が空中に浮いた。
- 位置と向きの両方を枝形状から導いた版は、接続は直ったが分布を捏造した。面積重み付きサンプリングは太い枝に葉を集中させ、主成分軸は符号を持たないため垂直に近い枝で下向きに確定し、樹冠がカーテン状に垂れた。

いずれも遠景の描画だけでは検出できず、利用者によるScene内の近接確認で判明した。このため `RenderTreeCloseupsForBatchMode` を常設し、樹冠端・見上げ・幹接合部の3視点をベイクごとに確認する。

樹冠はカード集合であるため、真横から見た個々のカードは細い筋として見える。カードごとのroll角の乱数化で目立ちにくくしているが、原理的には残る。

真下から見上げた樹冠はほぼ不透明で、空が見えない。星空ワールドとして木の下を鑑賞位置にする場合は、密度の再検討が要る。spawnは木から離れているため現状の導線では問題にならない。

カード樹冠は原本の葉envelopeより広がるため、Mesh実幅の検証上限を10.5mから12.0mへ緩めた。この検証は元々、木が横倒しになるimport不具合を捕捉するためのものであり、緩和後もその役割は保つ。

`Jacaranda_LOD0.asset` をリポジトリから外したため、追跡対象は2.52MBの出荷Meshだけになった。再ベイクには原本FBXと同様にローカルの中間Meshが要る。手元に無い環境では出荷Meshをそのまま使う。

実機での描画時間は未計測である。三角形数はQuest予算内に収まったが、alpha testのoverdrawはtile GPUで別途コストになるため、樹冠を見上げる状態でのGPU時間は実機計測が必要である。
